# The catalogue of mutations: one entry per line, five fields separated by TAB.
#
#   id <TAB> file to mutate <TAB> exact text to replace <TAB> text that replaces it
#        <TAB> tests of tests/ that must fail when the mutation is applied
#
# THE CATALOGUE IS SEVERAL FILES
#
# This file and every tests/mutation/catalog.d/*.txt, read in the order LC_ALL=C
# sorts their names, are one catalogue with one set of ids: an id in two entries is
# refused wherever they are. The format is the same in all of them. The entries of
# an area live in the file that names it (hygiene.txt for the scan of credentials
# and the identity of commits, callers.txt for the rule on what a caller of a
# reusable may switch off or pass, instrument.txt for the readers of the catalogue
# themselves), and this file holds the rest. A file stays under 400 lines of code:
# when one grows past it, it splits by what its entries sustain, not by size alone.
# The runner, the coverage check and the decision of which entries a pull request
# runs all read them this way; `run-mutations.sh --catalog <file>` reads one file.
#
# The text to replace has to appear EXACTLY ONCE in the file: a text that appears
# nowhere changes nothing and proves nothing, and one that appears twice is
# ambiguous. The runner refuses both, so an inert entry cannot sit in this file
# unnoticed. A text holds no TAB: the line carries exactly four, and a fifth
# would move every field after it. The text of a shell guard therefore starts
# after the indentation, never inside it.
#
# The tests named by an entry are the ones that must notice when it is applied.
# A suite that fails in a copy without git metadata is excluded: it fails there
# whatever the mutant is, and it would count as a kill that never happened.
#
# THE SUITES LEFT OUT, AND WHY
#
#   tests/ci/suites/check-suite-completeness.test.sh
#       Reads the base commit to scope the suites it runs. The copy is made
#       with `git archive HEAD` and carries no history, so it fails there
#       whatever the mutant is. Excluded by name in the runner.
#
#   tests/quality/hygiene/check-editorconfig.test.sh
#       Walks `git ls-files`. The copy carries no index, so it sees no tracked
#       file and fails. Excluded by name in the runner.
#
# Any OTHER suite that fails in a pristine copy is excluded as well, measured
# once per suite. On the machine this catalogue was measured on, that list was:
#
#   tests/build/build-repo-expiry.test.sh
#       Needs reprepro to build an archive with an expired Release, and reprepro
#       is not installed there, so the suite fails before it reaches a guard.
#       It is not named by any entry below.
#
# Every entry below was measured on that machine: with the mutation applied at
# least one of the suites it names goes red, and with the tree unmutated every
# suite of this repository that can run there passes.
#
# THE GUARDS THAT ARE NOT IN THIS CATALOGUE
#
# A guard with no entry here is not measured by the sweep, so every refusal of
# the scripts under scripts/ and keyring/upgrade/ and of the run: blocks of every
# workflow has to have an entry or a line in tests/mutation/exemptions.txt that
# says why it has none.
# scripts/quality/coverage/check-mutation-coverage.sh fails a pull request that leaves
# one with neither, and tests/quality/coverage/check-mutation-coverage.test.sh runs it in
# the suite job. A guard measured to survive is recorded there with what was
# measured, not left out in silence: an entry that survives makes the whole
# sweep red.
#
# THE ML-DSA-65 GUARDS ONLY A REAL SIGNATURE REACHES
#
# The verify-debs-pq-* entries name tests/verify/verify-debs-hybrid.test.sh,
# which needs no ML-DSA library. Three guards of the same check are reached only
# by a real ML-DSA-65 signature: the cryptographic verification itself, the walk
# over every configured key, and the refusal of a signature that does not
# verify. tests/verify/verify-debs-mldsa.test.sh kills them, and it needs
# cryptography 50.0.2, which CI installs only in that suite's own job. This
# sweep runs on the runner's python3-cryptography, where that suite fails
# without any mutation, so an entry naming it could not be run here. Each of
# the three was deleted by hand and that suite went red for it.
#
# Run: tests/mutation/run-mutations.sh [--list] [<id>]
