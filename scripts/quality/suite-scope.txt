# suite-scope.txt -- which paths can change each suite's verdict.
#
# WHAT THIS FILE IS
#
# The test job of .github/workflows/reusable-shell-ci.yml runs every suite on
# every pull request. Most of them are cheap; three are not, and their cost
# does not depend on the change: tests/verify/verify-published.test.sh,
# tests/publish/purge-cache/purge-cache-budget.test.sh and
# tests/publication/health-check/health-check-workflow.test.sh are integration suites that
# build a signed archive, serve it over a local HTTP server and wait on
# retries and budgets. Measured on this repository on 2026-11-06, the whole
# suite is 151.0 s locally and those three are 69.7 s of it (46 %).
#
# This file says, per suite, the paths whose change can alter what that suite
# concludes. A pull request that touches none of them cannot change that
# suite's verdict, so the suite does not need to run to learn something it
# already knows. The decision is made by scripts/quality/ci-job-scope.sh, in
# its `suites` mode, and the job and its required check `shell / test` still
# report exactly as before.
#
# WHY IT IS SAFE
#
#   * It fails open, in every direction. A suite with no entry here always
#     runs. A suite whose entry has no pattern is refused. A diff that cannot
#     be read, a rename, a copy, a type change, a push, a schedule or a
#     workflow dispatch runs every suite. A wrong skip lets a change merge
#     untested; a wrong run costs seconds. The asymmetry decides every
#     borderline case in favour of running.
#
#   * The decision is taken with the resolver and this map as they are in the
#     BASE commit, not as the pull request ships them. A pull request that
#     rewrites the map or the resolver to narrow its own scope gets the full
#     suite instead, because the base copy is what decides. This is the same
#     rule the shellcheck job of the reusable already follows for
#     scripts/quality/ci-job-scope.sh, and the rule the CI standard states:
#     a gate script is read from the base commit, never from the checkout of
#     the pull request it is judging.
#
#   * The map, the resolver and the runner are an input of every suite. A
#     change to any of the three runs the whole suite set, so the thing that
#     decides what runs cannot be changed in order to decide less, and the
#     thing that runs the suites cannot be changed in order to run fewer.
#     The rule is in scripts/quality/ci-job-scope.sh rather than in an entry
#     per suite here, so a suite added below later cannot forget it.
#
#   * The names of the suites here are the paths the workflow passes to
#     tests/ci/suites/check-suite-completeness.test.sh, so the workflow still
#     names every suite and tests/ci/suites/ci-runs-every-test.test.sh still
#     sees a complete list. Only the decision to EXECUTE a suite changes.
#
#   * A push to main runs every suite. Nothing is ever removed from the set
#     that runs there; the mechanism only ever removes suites from a pull
#     request, and only those a pull request cannot affect.
#
# HOW THE ENTRIES WERE DERIVED
#
# Each suite was run under strace on 2026-11-06 and the files it opened were
# recorded, so the sets below are measured rather than guessed. They were then
# widened to the area that contains them: a suite that read one file of
# scripts/verify/ depends on scripts/verify/, because the next change in that
# folder may be the one it reads.
#
# Two shapes need saying apart, because the measurement alone does not tell
# them apart:
#
#   * A suite that WALKS a tree -- find, ls, `git ls-files` -- depends on the
#     whole tree BY NAME. The coverage gate walks scripts/ and requires a
#     test of the same name in tests/, so its entry is scripts/** and
#     tests/**: a script added without a test, or a test removed while its
#     script stays, changes what it concludes.
#
#   * A suite that COPIES a tree into its fixture -- `cp -r scripts` -- and
#     then runs two of the copies depends on those two, not on the tree.
#     Copying is not reading: the members that are never executed cannot
#     change the verdict. The entries below that copy the tree name the
#     scripts they execute and whatever those read.
#
# PATTERN SYNTAX
#
#   *   matches within one path segment.
#   ?   matches one character within one path segment.
#   **  matches any number of segments, including none.
#   A bare path matches that path exactly.
#
#   scripts/verify/**     every file under scripts/verify/
#   .github/workflows/publish.yml   that one file
#   **                   every tracked file
#
# HOW TO EXTEND IT
#
# A new suite arrives without an entry, so it always runs until somebody
# writes one. That is the safe default and it is why the file is allowed to
# lag behind the suite list. When you add an entry, measure it the same way
# this one was measured: run the suite under strace and record the files it
# opens.
#
# ---------------------------------------------------------------------------
